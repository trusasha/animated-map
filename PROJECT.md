# Trip Animator — проект

Веб-приложение (localhost, десктоп + мобильный), которое превращает маршрут путешествия в анимированное видео для соцсетей: 3D-глобус, по маршруту едет/летит/плывёт 3D-фигурка, за ней остаётся след, камера следует за ней. На выходе — MP4 в форматах Instagram/TikTok/YouTube.

## Что умеет сейчас

- **Маршрут**: одна цепочка точек. У каждой точки, кроме первой, есть `leg` — как сюда добрались из предыдущей: тип перемещения (воздух / земля / вода) + фигурка + темп. Отдельного массива отрезков нет, поэтому точка не может оторваться от маршрута: удалили/переставили — соседи соединяются сами (`chain()` в `src/route.ts` после каждой правки и при загрузке: чинит пропавшие/битые участки, дубли id, диапазон видео на удалённые точки; старые сохранения с `legs[]` конвертируются). ↑/↓ меняет местами точки, а настройки участков остаются на своих позициях.
- **Ввод**: вручную (поиск мест с автокомплитом) или текстом/голосом/JSON-списком отрезков — OpenAI распознаёт речь и разбирает рассказ в точки и отрезки. Порядок точек сохраняется буквально (optional пропускается); способ передвижения ИИ пишет в саму точку, чтобы не разъезжался со списком. Координаты: ИИ даёт примерные, Nominatim (1 запрос/с) или Photon уточняют — берётся ближайший кандидат в 60 км; если никто не подтвердил, точка помечается ⚠ (`Stop.approx`) — проверить и поправить через 📍.
- **Траектории**: воздух — дуга по большому кругу с набором высоты; вода — большой круг по поверхности; земля — реальный маршрут по дорогам (OSRM), упрощённый и сглаженный (см. «Плавность»).
- **Анимация**: интро (облёт к старту) → отрезки → смена фигурки на остановках (уменьшение / вращение / появление; если фигурка та же — просто пауза `HOLD` = 1 с с плавным разворотом к следующему отрезку) → аутро (отлёт к общему виду). Фигурка плавно поворачивает, самолёт наклоняется при наборе высоты и снижении.
- **Фигурки**: 10 встроенных процедурных 3D-моделей (самолёт, вертолёт, машина, эндуро, спортбайк, автобус, поезд, велосипед, лайнер, парусник), свои `.glb`, генерация 3D по фото (fal.ai Hunyuan3D v3, ~2 мин, фон вырезается сам; HEIC конвертируется через `sips`). Добавление — модалка: фото/GLB, название, тип (воздух/земля/вода или «любой» — тогда фигурка доступна во всех типах). Ориентация авто: длинная сторона по курсу (фото сбоку даёт модель вдоль X). Через ✎ — имя, тип, поворот шагами 90°, размер; поза хранится в `models.pose` и применяется везде, кэши фигурок ключуются по `url+поза`. Выбор — сеткой 3D-миниатюр.
- **Превью** в реальном времени с перемоткой; **экспорт MP4** покадрово (9:16, 4:5, 1:1, 16:9). Окно экспорта сначала грузит тайлы и показывает кадр с подписями; заголовок, подпись отрезка и прогресс-бар включаются отдельно (`TripData.overlay`), атрибуция карты есть всегда (лицензия тайлов). На телефоне — «Поделиться».
- **Стили карты**: спутник (Esri), улицы и тёмная (OpenFreeMap), «Японская гравюра» (`src/ukiyoe.ts`: свои слои поверх тех же векторных тайлов OpenFreeMap — бумага васи, вода индиго, тушевые берега и дороги; текстура бумаги рисуется на canvas через `setMissingStyleImageResolver`) — всё без ключей. Фон-бумага — заливка полигоном мира: слой `background` на рельеф не ложится. Шрифт пока Noto Sans (кисточный требует своих глифов).
- **Рельеф**: 3D-terrain (Terrarium DEM на AWS, ×1.5) + отмывка во всех стилях. Фигурка стоит на рельефе, дуги самолётов идут по линейному пандусу между высотами аэропортов.
- **Предзагрузка тайлов** — потоковая, как буферизация видео: камера мгновенно (без рендера) пробегает таймлайн, `map.coveringTiles()` собирает тайлы в порядке времени, они качаются параллельно в HTTP-кэш браузера (хосты Esri и S3 шардированы — все HTTP/1.1, по 6 соединений на хост). Превью и экспорт стартуют, как только закэшированы первые `BUFFER_AHEAD` = 10 с ролика; дальше загрузка идёт в фоне впереди воспроизведения, а если плеер её догонит — держит кадр («буферизация…»). 30 участков: старт через ~15 с с холодного кэша (было ~20 мин → 81 с → 4 с; рост — из-за фиксированной детализации на общем плане интро).
- **Старт/финиш участка**: участок соединяет соседние точки, поэтому старт всегда = финиш предыдущего. «📍 Финиш» + клик по карте или перетаскивание маркера у выбранного участка переносит точку; оба участка, которые её делят, перестраиваются, имя — обратным геокодингом Photon (при ошибке остаётся старое).
- **Участок для видео**: в блоке «Видео» — от точки N до точки M (`TripData.range`, по id точек; один непрерывный кусок). Превью и экспорт строят таймлайн только по нему, остальной маршрут в редакторе — блёклый пунктир (в превью/видео скрыт), в панели приглушён.
- **Без смены детализации при зуме**: у каждого источника тайлов MapLibre-функция выбора уровня (`calculateTileZoom`, берётся через `setSourceTileLodParams`) получает сдвиг: вместо текущего зума — самый детальный зум текущего куска таймлайна (`detailZoom`: интро, отрезок, остановка, аутро), не больше +`MAX_LOD_BIAS` = 2 уровня. Внутри отрезка уровень тайлов не меняется, пока камера отъезжает/наезжает; смена возможна только на стыках кусков. Цена — ~2.4× тайлов в кадре. Предзагрузка планирует тайлы той же функцией; у каждого тайла таймаут 10 с, иначе один зависший запрос держал буфер (было 15 мин).
- **Выбор участка**: клик по участку в панели (или по названию точки) подсвечивает его на карте и наводит камеру.

## Запуск

```bash
npm install
cp .env.example .env   # OPENAI_API_KEY, опционально FAL_KEY
npm run dev            # http://localhost:5173
npm run check          # self-check таймлайна и цепочки маршрута
npm run build && npm start
```

| env | зачем |
|---|---|
| `OPENAI_API_KEY` | голос + разбор маршрута |
| `OPENAI_MODEL` / `OPENAI_TRANSCRIBE_MODEL` | по умолчанию `gpt-4.1-mini` / `gpt-4o-mini-transcribe` |
| `FAL_KEY` (или `FAL_AI_API_KEY`) | 3D по фото (~$0.375 за модель, оплата по факту) |
| `DATABASE_URL` | пусто — локальный Postgres (PGlite); строка Supabase — переезд |
| `HOST` | `0.0.0.0` открывает сервер в LAN (вместе с ключами!) |
| `HEALTH_TOKEN` | открывает `/api/health/stats` (`?token=` или заголовок `x-health-token`); без него статистика открыта только при выключенной авторизации |

## Мониторинг

- `GET /api/health` — для uptime-мониторов: без авторизации, пингует БД; 200 или 503, версия, аптайм, память сервера.
- `GET /api/health/stats?hours=24` — что происходило у пользователей: визиты, воронка экспорта (open → start → done / error / **crashed**), ошибки клиента и сервера, последние проблемы с данными.
- События пишутся и в `data/logs/actions.jsonl`, и в таблицу `events` (хранятся 90 дней, RLS включён — читает только сервер).
- Каждый визит шлёт `session.start` с устройством (UA, память, ядра, экран); необработанные ошибки — `client.error`.
- **Вылеты экспорта:** пока идёт экспорт, в `localStorage` лежит метка с прогрессом и памятью. Если вкладку убила ОС (нехватка памяти), метку никто не стёр — следующий визит шлёт `export.crashed` (или `export.abandoned`, если вкладку перед этим свернули).

### Ключевые решения

- **Детерминированный таймлайн.** `sample(timeline, t)` полностью определяет кадр: позицию, высоту, курс, фигурку, масштаб, камеру. Превью и экспорт используют одну функцию, поэтому видео совпадает с превью. Покрыто `src/timeline.check.ts`.
- **3D на глобусе.** MapLibre v6 globe + Three.js в custom layer. Фигурка рисуется в локальной системе east-north-up (метры). Матрица проекции — линейная смесь globe- и mercator-матриц по `projectionTransition`, так же как MapLibre смешивает проекции в шейдере, поэтому переход globe→mercator на зуме ~11–12 плавный. Размер фигурки привязан к пикселям (`FIG_PX`), а не к метрам.
- **Дуги самолётов** — `Line2` (толщина в пикселях) в координатах относительно фигурки для точности, плюс невидимая сфера-окклюдер, чтобы дуга пряталась за горизонт. Ловушка: three кэширует число сегментов instanced-геометрии, поэтому растущую линию нужно пересоздавать (`setLine`).
- **Экспорт** покадровый: `setFrame` → ждём idle карты → рисуем кадр + оверлей на 2D-canvas → `VideoEncoder`. Скорость рендера не зависит от FPS, кадры не теряются.
- **Плавность**: дороги упрощаются (DP) при загрузке; в таймлайне наземные/водные отрезки сглаживаются гауссом переменной ширины — max(скорость/`MAX_TURN`, `MIN_BEND_PX` × м/px при зуме камеры), путь зеркалится за концами, чтобы остановки не сдвигались. Курс фигурки — строго касательная к сглаженному пути. Глобальные крутилки в `src/timeline.ts`; в отрезке (земля/вода) ползунок «Сглаживание» — множитель ширины (`Leg.smooth`, 0 = точно по дороге).
- **БД**: одна таблица `trips` (маршрут целиком в `jsonb`) + `models` (`mode`, `pose` jsonb). SQL одинаковый для PGlite и Supabase, колонки добавляются `alter table … if not exists`. Пути маршрутов кэшируются в `stop.leg` (`path` + `pathKey` = id предыдущей и этой точки + тип); перенос точки сбрасывает `pathKey` у неё и у следующей.
- **Рельеф**: тайлы Terrarium содержат батиметрию — протокол `dem://` обнуляет высоты ниже 0, иначе океаны проваливаются, а корабли уходят под воду. Hillshade берёт отдельный источник `hill` (на общем с terrain MapLibre ругается). Высота фигурки — `queryTerrainElevation`, она уже включает exaggeration.
- **Внешние сервисы**: бесплатные без SLA — Esri / OpenFreeMap (тайлы), AWS Terrarium (высоты), OSRM demo (дороги), Nominatim и Photon (поиск мест); платные по ключу — OpenAI (голос, разбор), fal.ai (3D по фото).

### Логи

`data/logs/actions.jsonl` — по строке JSON на действие: правки точек/участков, диапазон, превью (с временем предзагрузки), экспорт, ошибки клиента, разбор маршрута (текст + результат), ошибки сервера. Первое место, куда смотреть, когда «что-то сломалось».

### Известные ограничения

- Пока идёт рендер, вкладку нельзя сворачивать: рендер идёт в браузере.
- Микрофон на телефоне работает только по HTTPS.
- Водные маршруты — по прямой (большой круг), без обхода суши.
- DEM ограничен зумом 12 (дальше растягивается) — ради скорости предзагрузки.
- Публичные OSRM, Photon и Nominatim медленные и без гарантий (Photon бывает 503). Разбор маршрута из ~30 точек занимает ~1.5 мин из-за лимита Nominatim. Японские и редкие места бесплатные геокодеры находят плохо — отсюда ⚠.
- Нет авторизации: приложение однопользовательское, локальное.
- Через карту переносится только финиш участка; старт первого участка — только поиском/удалением точки.
- Интро и аутро всё ещё могут менять детализацию тайлов: запас ограничен `MAX_LOD_BIAS` = 2 уровня.
- PGlite (`data/pg`) нельзя открывать двумя процессами одновременно — ломается WAL. Перед вторым `npm run dev` остановите первый.

## Планы / идеи на будущее

- **Supabase**: прописать `DATABASE_URL` (уже работает) и перенести `data/uploads` в Supabase Storage; добавить авторизацию и мультипользовательский режим.
- **3D по фото**: работает (data-URI принимается). GLB тяжёлые (~35 МБ, ~300k вершин) — стоит децимировать/сжимать (gltf-transform). Возможно, дать выбор модели (Trellis — дёшево, Tripo — качество).
- **Морские маршруты** с обходом суши (searoute и подобное).
- **Камера**: «кинематографичный» режим с поворотом камеры за курсом; настройка наклона и зума.
- **Видео**: музыка и звук, фото/подписи на остановках, даты, свой текст оверлея, выбор длительности под формат.
- **Экспорт в фоне / на сервере** (headless), чтобы не держать вкладку открытой.
- **Свой тайл-сервер / платный провайдер** (MapTiler, Mapbox) для стабильности и качества.
- **HTTPS для локальной сети** (mkcert), чтобы с телефона работал микрофон.
- **«Гравюра»**: кисточный шрифт (свои PBF-глифы); ИИ-подложка — регион маршрута, перерисованный в стиле укиё-э (img2img), как картинка на карте для общих планов; фильтр-шейдер «мультяшности» поверх кадра.
- **Предзагрузка**: быстрее старт интро (меньший `MAX_LOD_BIAS` на общем плане).
